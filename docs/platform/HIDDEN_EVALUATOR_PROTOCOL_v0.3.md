# First Principles LLM Research
## Hidden Evaluator Probe Protocol v0.3

**Date:** 2026-09-18  
**Status:** TRANSPORT FROZEN / CAUSAL-ATTENTION ADAPTER PROVISIONAL  
**Applies to:** `phase1-causal-attention@1.0`

## 1. Purpose

The hidden evaluator must test learner code without placing private test source, fixture-generation logic, private seeds, or expected-answer logic in the learner container.

The protocol therefore separates execution into two processes:

```text
untrusted learner probe <---- Unix domain socket ----> trusted hidden evaluator
```

The learner probe sees the submitted workspace. The hidden evaluator sees the private test bundle. Neither sees the other's filesystem mount. Both have external networking disabled.

This protocol is an execution boundary, not a promise that a malicious learner cannot observe individual black-box inputs sent for evaluation. Hidden-test robustness must come from randomized/repeated trials, not from assuming input values are invisible.

## 2. Non-negotiable mount invariant

### Learner probe container

May mount:

- learner workspace read-only;
- one per-execution IPC directory read/write;
- bounded tmpfs supplied by the runtime.

Must not mount:

- private hidden-test bundle;
- hidden evaluator source;
- hidden seed files;
- platform secrets;
- database credentials;
- GitHub credentials;
- Docker/container-runtime socket;
- worker host root or arbitrary host paths.

### Hidden evaluator container

May mount:

- private hidden-test bundle read-only;
- the same per-execution IPC directory read/write;
- bounded output directory read/write;
- bounded tmpfs supplied by the runtime.

Must not mount:

- learner workspace;
- GitHub checkout/materialization directory;
- platform secrets unrelated to evaluation;
- database credentials;
- Docker/container-runtime socket.

The worker contract tests must reject any argument construction that violates this separation.

## 3. Transport

Protocol identifier:

```text
fpllm-probe/1
```

Transport:

```text
AF_UNIX / SOCK_STREAM
/run/fpllm-ipc/probe.sock
```

Readiness marker:

```text
/run/fpllm-ipc/probe.ready
```

The readiness marker is operational only. It is not trusted evidence. The evaluator must still perform a protocol handshake before accepting responses.

Framing:

- UTF-8 JSON Lines;
- exactly one JSON object per line;
- maximum encoded frame size: 1 MiB;
- request and response IDs are opaque strings generated by the evaluator;
- no executable code, pickle, Python marshal objects, shell fragments, arbitrary import paths, or arbitrary callable names are accepted from either side.

## 4. Handshake

Evaluator request:

```json
{
  "protocol": "fpllm-probe/1",
  "requestId": "r-0001",
  "operation": "describe",
  "payload": {}
}
```

Probe response:

```json
{
  "protocol": "fpllm-probe/1",
  "requestId": "r-0001",
  "ok": true,
  "result": {
    "interface": "causal-attention-v1",
    "capabilities": ["attention.forward", "attention.memory_trace"]
  }
}
```

The evaluator rejects protocol mismatch, duplicate response IDs, unknown capabilities, malformed envelopes, oversized frames, or responses after a request deadline.

## 5. Envelope

Request:

```json
{
  "protocol": "fpllm-probe/1",
  "requestId": "opaque-evaluator-id",
  "operation": "allowlisted.operation",
  "payload": {}
}
```

Successful response:

```json
{
  "protocol": "fpllm-probe/1",
  "requestId": "opaque-evaluator-id",
  "ok": true,
  "result": {}
}
```

Failed response:

```json
{
  "protocol": "fpllm-probe/1",
  "requestId": "opaque-evaluator-id",
  "ok": false,
  "error": {
    "code": "ADAPTER_EXECUTION_FAILED",
    "message": "bounded diagnostic text"
  }
}
```

Learner-controlled traceback text is never treated as structured evidence. Diagnostic strings are length-bounded before persistence or display.

## 6. Causal Attention adapter

The runtime image, not the learner repository, supplies the `causal-attention-v1` adapter. The adapter maps a fixed course-version interface onto learner code.

The first required operations are:

### `attention.forward`

Purpose: support randomized numerical equivalence checks without disclosing expected outputs.

The evaluator provides a bounded trial descriptor containing only values required to construct one legal input/configuration. The learner probe executes the course-defined attention interface and returns a bounded tensor result representation plus runtime metadata required by the protocol.

The evaluator independently computes the reference result and decides pass/fail. Expected values are never sent to the learner probe.

### `attention.memory_trace`

Purpose: support the documented `attention.no_permanent_kv_repeat` invariant.

The adapter executes the same course-defined interface while runtime-owned instrumentation records only the structural events required by the invariant. The response contains the bounded trace schema defined by the versioned adapter contract.

The learner repository does not choose arbitrary trace fields or evaluator callbacks.

The exact Python symbol mapping, legal shape set, tensor serialization format, trial count, tolerances, randomized seed schedule, and trace schema remain **PROVISIONAL** until the actual `phase1-causal-attention@1.0` public interface is wired into the runtime image. They must be versioned with the test bundle before v0.3 release.

## 7. Request limits

For one hidden evaluation execution:

- maximum requests: 512;
- maximum request frame: 1 MiB;
- maximum response frame: 1 MiB;
- maximum evaluator wall-clock: the `SandboxJob.execution.timeoutSeconds` limit;
- per-request deadline: bounded by the remaining evaluator wall-clock;
- evaluator may terminate the probe immediately after the final request;
- malformed protocol traffic is an infrastructure/protocol failure, not automatically a mastery failure.

The hidden evaluator must avoid unbounded tensor dimensions, allocations, recursion, output capture, or request queues.

## 8. Result semantics

The private evaluator produces the normal worker evidence document only after it has completed its private reasoning:

```json
{
  "schemaVersion": "1",
  "testBundleId": "phase1-causal-attention@1.0",
  "results": [
    {
      "groupId": "randomized_numerics",
      "invariantId": "attention.randomized_numerics",
      "passed": true,
      "summary": "bounded learner-visible diagnostic"
    },
    {
      "groupId": "no_permanent_kv_repeat",
      "invariantId": "attention.no_permanent_kv_repeat",
      "passed": true,
      "summary": "bounded learner-visible diagnostic"
    }
  ]
}
```

The worker validates the invariant IDs and completeness before persistence. Hidden evaluator process exit code is reserved for evaluator/protocol/infrastructure failure. A legitimate learner invariant failure is encoded as `passed: false` in an otherwise valid result document.

## 9. Threat model

The boundary is designed to prevent accidental or straightforward disclosure of private evaluator source and fixtures to learner code. It specifically prevents the previous unsafe topology where learner code and the private bundle were mounted into the same container.

It does not claim protection against every side channel or adversarial strategy. In particular:

- the learner process necessarily observes black-box inputs sent to it;
- a stateful learner implementation may adapt to sequences of requests;
- timing and resource use can reveal coarse information;
- Docker alone is not a perfect security boundary.

Mitigations for the course setting include randomized trials, multiple seeds, bounded protocol behavior, immutable runtime/test identities, dedicated worker hosts, no external network, and evaluator decisions made outside the learner mount namespace.

## 10. Release evidence required

Before v0.3 can leave draft status, staging evidence must show:

```text
1. learner container mount inspection: private bundle absent
2. evaluator container mount inspection: learner workspace absent
3. evaluator successfully completes a known-good immutable commit
4. evaluator records a deterministic hidden failure for a known-bad immutable commit
5. experiment gate opens only for the passing evidence path
6. no GitHub/database/platform secret is present in either container environment
7. same commit + same bundle/runtime identities can be re-executed as a new evidence record
```

Unit tests that only inspect Docker argument arrays are necessary but not sufficient for this release gate.
